17/**
18 * @brief Data provider sampling the instance data of a run from random expressions.
19 *
20 * The data is read from a CSV table with the columns `INSTANCE_ID`, `NODE_ID`, `INITIALIZATION`,
21 * `DISCLOSURE`, `READY` and `COMPLETION`, of which the table may omit the trailing ones. The expressions may
22 * use random functions. The global values are sampled once, with the seed of the data provider. Every
23 * initialization and disclosure of an instance is sampled for each scenario, with the seed of the
24 * scenario, which is the seed of the data provider plus the realisation the scenario is created for, in the
25 * order of the rows. A run on a scenario proceeds as on the dynamic data provider with the values and
26 * disclosure times sampled, but what is disclosed is an announcement, which the realisation may contradict:
27 * the ready expressions of an activity give the status a token arriving at it becomes ready with, once the
28 * timestamp of this status is reached, and the completion expressions of a task give the status it
29 * completes with. Every random expression of an instance and a node is evaluated with a random number
30 * generator of its own, seeded from the seed of the scenario and the identifiers of the instance and the
31 * node, so that a realisation depends on nothing but the seed, the model and the instance data.
32 *
33 * A fork of a run with seed `r` and index `i` has the seed `r + i + 1`. It keeps what the run has revealed
34 * and samples everything else anew. The initializations are disclosed with clock ticks, so that the fork
35 * of a run at time `t` keeps every initialization disclosed by `t` and samples every other one anew, its
36 * timestamp and disclosure time being sampled again up to @ref maxResamplingTries times while they precede
37 * `t + 1` and then set to `t + 1`. The tokens awaiting their ready or completion event in the installed
38 * system state are those whose statuses have not been revealed, and these statuses are computed anew when
39 * the state is installed, a timestamp being sampled again up to @ref maxResamplingTries times while it
40 * precedes `t`, if one of the expressions assigns it, and then set to `t`. A timestamp of `t` is admissible,
41 * since an event of an instant may follow a decision of that instant. A status computed for a token arriving
42 * at an activity or becoming busy at a task is computed as in any run.
43 */
