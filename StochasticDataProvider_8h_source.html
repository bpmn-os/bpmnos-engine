18/**
19 * @brief Data provider sampling the instance data of a run from random expressions.
20 *
21 * The data is read from a CSV table with the columns `INSTANCE_ID`, `NODE_ID`, `INITIALIZATION`,
22 * `DISCLOSURE`, `READY` and `COMPLETION`, of which the table may omit the trailing ones. The expressions may
23 * use random functions. The global values are sampled once, with the seed of the data provider. Every
24 * initialization and disclosure of an instance is sampled for each scenario, with the seed of the
25 * scenario, which is the seed of the data provider plus the realisation the scenario is created for, in the
26 * order of the rows. A run on a scenario proceeds as on the dynamic data provider with the values and
27 * disclosure times sampled, but what is disclosed is an announcement, which the realisation may contradict:
28 * the ready expressions of an activity give the values a token arriving at it becomes ready with, and the
29 * completion expressions of a task give the status it completes with. A ready expression assigning the
30 * timestamp must be the first ready expression of its node and may read only what the scope inherits, the
31 * status the token holds, the data of the enclosing instances and the globals: it is sampled when the token
32 * arrives and determines when the token becomes ready. The other ready expressions are applied when the token
33 * becomes ready, over the initial values of the scope instance, and may assign a status attribute or a data
34 * attribute the scope owns, an object among them, or an element or field of such an object; a completion expression
35 * assigns a status attribute, a status object, or an element or field of a status object. An object initializer of
36 * an instance is sampled for each scenario like a value, in the order of the rows. An initialization, a member of an
37 * object initializer and a disclosure may read only the global values, the initial objects of the model, and what
38 * the rows of the instance read so far give, a disclosure also what its own row gives; any other read is refused
39 * when the instance data are read, and an expression yielding no value is refused when it is sampled. Every random
40 * expression of an instance and a node is evaluated with a random number
41 * generator of its own, seeded from the seed of the scenario and the identifiers of the instance and the
42 * node, so that a realisation depends on nothing but the seed, the model and the instance data.
43 *
44 * A fork of a run with seed `r` and index `i` has the seed `r + i + 1`. It keeps what the run has revealed
45 * and samples everything else anew. The initializations are disclosed with clock ticks, so that the fork
46 * of a run at time `t` keeps every initialization disclosed by `t` and samples every other one anew, its
47 * timestamp and disclosure time being sampled again up to @ref maxResamplingTries times while they precede
48 * `t + 1` and then set to `t + 1`. The tokens awaiting their ready or completion event in the installed
49 * system state are those whose values have not been revealed: the ready timestamp of a token awaiting its ready
50 * event and the completion status of a token awaiting its completion event are computed anew when the state is
51 * installed, a timestamp being sampled again up to @ref maxResamplingTries times while it precedes `t`, if an
52 * expression assigns it, and then set to `t`. A timestamp of `t` is admissible,
53 * since an event of an instant may follow a decision of that instant. A status computed for a token arriving
54 * at an activity or becoming busy at a task is computed as in any run.
55 */
